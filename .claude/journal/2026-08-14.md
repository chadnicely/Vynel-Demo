## tool-policy arc (worktree `mcp-tool-policy`) — internal MCP tools × mode × consumer kind

Six slices, each gated + reviewed + committed: SDK ^0.3.231 · permission re-plumb (killed the
SHADOWED hole — bare `mcp__*` wildcards were auto-approving every MCP tool before `canUseTool`;
one `tool-approval-policy.ts` decision home now drives callback + hook, bwbg runs under SDK
`'default'`, pure bypass binds no callback) · tier filtering at composition (`featureGatedTools`
— out-of-tier tools invisible, not 403s) · `tool_policies` overrides + effective resolver
(leaf-owned in capabilities, all-null = inherit/delete) · surface catalog replacing 9 hardcoded
arrays + `/tool-policies` routes (x-mcp OFF) + fully-editable admin matrix with the first
capability toggles UI · bounded `ask_user` on channel turns (10-min expiry, Telegram nudge,
sessionId stamped).

**Learned:**

- The catalog is the policy source: attaching a server at a turn site without granting the
  surface in the catalog means the policy layer denies the very tool the turn composed — the
  Slice-5 reviewer caught the ask server shipping inert on exactly its target surface. Pinned
  with a real-catalog compose test (real resolver + real DB, no mocks) so the class can't
  recur.
- An unguarded `setTimeout` callback that can throw is a process crash, not a failed request —
  timer callbacks have no upstream catch. Guard the bookkeeping, still resolve the waiter.
- `cmd.exe /c "pnpm test" | tail` masks the gate's exit code with tail's — redirect to a file
  and check `$?`.
- Behavior-neutral re-plumbs want a de-facto-behavior matrix test FIRST (5 modes × 3 classes),
  then the rewire — the matrix caught two would-be regressions before review.

Gate at close: 780 files / 4,818 tests green. Decisions + deferrals in
`docs/module-notes/tool-policy.md`.

Chad's pivot on landing the first arc: the matrix is OPERATOR power → author it in
cloud-admin-web, bake the map into each desktop release (no runtime fetch — changes ship
with versions), keep the local panel on top. Four slices: contracts catalog snapshot +
parity guard (127 entries; unions moved to contracts so the hub never imports the product
engine) · hub `tool_policy_defaults` + sha256-content-versioned `/map` export · portal
ToolPolicyView (agent-built to spec) · release bake + the engine's three-layer resolve
(code → baked → user) applied inside `resolveSessionToolPolicies` with zero call-site
threading.

**Learned:**

- A committed generated file OUTSIDE the `src/generated/` globs is a time bomb: `pnpm
  format` would rewrite it and break its own parity guard. Emit generated artifacts into
  the ignored convention path from day one.
- `vi.mock` stubs of a package are a standing contract: adding an export to the real
  package breaks every stub-consumer at RUNTIME of the tests, not typecheck — the same
  gate failure twice across two arcs. Grep for `vi.mock('<pkg>')` when widening a barrel.
- Content-hash versions need canonicalization at WRITE time (surface order, JS-side
  codepoint sort) — DB collation and UI tick order are both nondeterminism sources the
  hash must never see.

Gate at close: 793 files / 4,877 tests green.
