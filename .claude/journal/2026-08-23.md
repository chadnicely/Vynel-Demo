# 2026-08-23

## New-workspace wizard — Slice 1, the AI seam (from Chad's `design/mission-control-prototype`)

The 13-screen "Walk me through it" wizard starts its move to main. This slice is the engine half:
two best-effort one-shots on the provider contract (`studyRivalSite`, `synthesizeWorkspacePlan`),
their Claude implementations over the existing `runClaudeDistillTurn`, and the two routes under
`/workspaces/wizard`. Note: `docs/module-notes/new-workspace-wizard.md`.

**Learned:**

- **The demo's nouns encode its schema.** "New app", "project inside a workspace", "which account
  builds" all came from the design branch's two-level workspace split and per-project accounts —
  decisions main never took. Kafi's one-line corrections ("it's a new workspace", "accounts are
  global") each collapsed a whole slice of plumbing. Name the entity main actually creates before
  porting a single screen; the route, the SDK namespace and the table name follow from it.
- **Folder first is also a security decision.** Moving the folder pick to screen 1 let the one-shots
  dispatch from the user's own folder instead of the global root dir — and the reviewer's catch is
  worth keeping: a toolless distill still loads that folder's `CLAUDE.md` / `.claude/settings*.json`
  (`settingSources: ['user','project','local']`). Same exposure as opening it as a workspace, but say
  so in the comment rather than claiming "nothing happens there".
- **Root prettier is the web app's style.** `prettier --write` on a package test rewrote it to double
  quotes + semicolons; packages are single-quote/no-semi. The existing package tests all "warn" for
  the same reason — run prettier on packages only with explicit `--single-quote --no-semi
  --print-width 100 --trailing-comma all`, or not at all.
- **A provider-contract method fans out to every inline fake.** Two default-null methods on
  `AiAgentProvider` broke three `as AiAgentProvider` object-literal fakes at typecheck (and the
  branch's own commit had patched exactly those three). Grep `discoverModels: async () => null` for
  the full list; one of them (`providers/index.test.ts`'s degraded provider) spreads
  `makeFakeProvider()` and needs nothing.
- **Don't rename files while the full suite runs.** The first full run reported one red — the SDK
  namespace pin — from the pre-rename `newApp` namespace; the second run, post-rename, was clean.
  Kill or wait, then rename, then run once.

## New-workspace wizard — Slice 2, scaffold + the stored brief

Finish made real: `scaffoldWorkspace` (folder inside the user's chosen one, README, `.gitignore`,
best-effort git, the row + the brief in one transaction), the `workspace_briefs` table, and the
`get_workspace_brief` read tool so a resumed session re-reads the approved plan.

**Learned:**

- **A sealed op that owns its transaction can't co-commit a sibling row.** `createWorkspace` wrapped
  its own `withTransaction`; inserting the brief after it left a window where the folder cleanup
  orphaned a committed row (reviewer catch). The fix that keeps every caller intact: extract the sync
  body as `createWorkspaceWithin(tx, input)` and let the composite op own the transaction. Expect
  this shape again whenever a wizard writes "the thing + what it knows about the thing".
- **The kernel stays dependency-free, so JSON it stores is opaque.** `@vynel/db` has no `@vynel/*`
  deps; the plan/answers shapes live in `@vynel/contracts` and the owning leaf casts once at its
  boundary (`toWorkspaceBrief`). The alternative — vertical-slicing one table out of a kernel-owned
  domain — would split `workspaces` in two homes. Cast with a WHY, validate at the api edge.
- **A git scaffold needs its `.gitignore` before the first `add`.** `.vynel/` (and the transcript
  images chat drops under it) would otherwise ride the primary session's first `git add .`.
- **Route tests stub the package barrel, not the process.** The scaffold shells out to git; the
  route test `vi.mock('@vynel/workspaces', …)`s only `scaffoldWorkspace` (importOriginal for the
  rest) and proves what the route owns — body validation, the resolved user, absent-not-undefined
  optionals, the response shape. The real op is covered at the leaf with an injectable runner.
- **`git commit` on a fresh machine has no identity.** `-c user.name=Vynel -c user.email=…` on the
  commit only — otherwise the scaffold's first commit fails on exactly the users it is for.

## New-workspace wizard — Slices 3 + 4, the screens and the door

Chad's twelve screens on main's `Modal` + Tailwind, the door in front of every "New workspace",
and the kickoff that seeds the stored brief into the new chat.

**Learned:**

- **Port the logic, rebuild the skin.** The branch's steps were ~530 lines of script under ~1,700
  lines of scoped CSS on another token set. The script ported near-verbatim (the synthesis-race
  guards and their tests included); the CSS was thrown away for Tailwind over the app's tokens
  plus one `wizard-classes.ts` of shared strings. Count the script, not the file, when sizing a
  UI port.
- **jsdom events are not cancelable by default.** A `persistent` Modal that blocks Escape via
  `preventDefault()` looked broken in its test until the dispatched `KeyboardEvent` got
  `cancelable: true` — reka's layer honours `defaultPrevented` exactly as documented.
- **A seed for the next screen must be set after the switch renders.** `ui.composerSeed` is consumed
  by whichever composer's watcher runs first; set it in the same tick as `addTab` and the chat you
  were leaving eats it. `addTab` → `await nextTick()` → seed.
- **`prettier --write` on a pre-existing web file is noise, not a fix.** `AppShell.vue` was never
  prettier-clean, so formatting it rewrote unrelated lines into the diff. Format NEW web files with
  prettier (that is the house style there); never `--write` an existing file you only edited.
- **A form draft shared with child screens is provided, not passed.** The branch's steps wrote
  into an `answers` prop (`props.answers.idea = …`) — zero precedent on main, and ESLint's green
  was hollow (`vue/no-mutating-props` is not active: the flat config spreads only
  `recommended.at(-1)`). `provide`/`inject` via `useWizardAnswers()` keeps the ergonomics and the
  rule; the DOM-driven tests did not change a line.
- **A lit chip that changes nothing is a dead button.** The advanced stack picks were stored and
  highlighted and read by nobody (reviewer catch). Fold every non-default pick into the brief's
  "Also follow" line — the cheapest way to make a choice real is to make it reach the session.
- **An external-command error is a user-facing string — and it echoes argv.** Node's execFile
  failure message is `Command failed: git … clone -- https://user:TOKEN@host/x.git …`; surfacing
  it raw would show a pasted token back on screen (reviewer catch on the clone door). Map the
  three real cases (`ENOENT` → git missing, `killed` → timeout, git's own `fatal:` line) and
  drop any `Command failed` line before the text reaches a `ValidationError`.
- **Everything after "the folder exists" belongs in one try/rm.** The clone wrapped only git;
  `createWorkspace` could still throw (path dedup spans archived rows) and orphan a successful
  clone with no way out but Explorer. Same shape as the scaffold: make the folder via
  `createChildDirectory` (one home for the name rules), then one `try` around the rest.
- **"Pick a folder" means THAT folder, every time.** The first cut treated the pick as a parent and
  minted a child from the name — so the wizard asked for the name twice and the clone made
  `vynel-beta\vynel-beta` (Kafi's live smoke). The register dialog already had the right model:
  the pick is the workspace, the name follows the folder. When three doors share a picker they
  must share its meaning; the fix deleted code (`folderName`, a second input) rather than adding.
- **Type the wire off the SDK, never off a server package.**

## GitHub + git — Slice 1, the connection

One GitHub sign-in for the app, over the `gh` CLI, with the device-flow code shown inside Vynel.

**Learned:**

- **Ask "what can the sessions already do?" before building an integration.** The first plan had an
  OAuth app, a sealed token and an API client. Kafi's one question — "gh can handle all kinds of
  API, and Claude has git/gh on Bash" — deleted all three: `gh` signs in, keeps the token, and does
  repos/PRs; git's own credential helper pushes. Vynel's whole job became status + an in-app sign-in.
- **A non-TTY spawn is the honest way to drive an interactive CLI, and its one assumption must be
  named.** `gh auth login --web` with stdin ignored should print the one-time code and poll on its
  own; the relay captures the code from the output. Whether it truly never prompts on this box is
  the live smoke — the terminal handoff from Chad's branch stays the fallback.
- **`promisify(execFile)` puts empty `stdout`/`stderr` strings on EVERY rejection.** Branching on
  "did it write output?" to tell a missing binary from an exit-1 therefore never fires — a missing
  `gh` read as "installed, signed out", and the test passed because its fake error lacked the
  strings (reviewer catch, verified live). Branch on `error.code === 'ENOENT'`, and shape fakes the
  way Node actually throws.
- **SDK path params are positional.** `vynel.github.getSignIn(loginId)`, not `({ loginId })` — the
  generated client flattens single path params; typecheck catches it, the composable's tests do not. The account step first imported
  `AuthenticationStatus` from `@vynel/providers` — a type-only import, but the wrong dependency
  direction for the web app. `Awaited<ReturnType<VynelClient["providers"]["getAuthStatus"]>>` is the
  same shape from the right side of the seam.

## GitHub + git — Slice 2, the git home + the facts

One runner for Vynel's own few git calls, and the truth about the folder on the workspace header.

**Learned:**

- **Two different ENOENTs.** `execFile` with a vanished `cwd` fails with the same `ENOENT` a
  missing binary gives. A facts reader that branches on the code alone would call a deleted
  workspace folder "git not installed". `stat` the folder first; then ENOENT means git.
- **One `git status --porcelain=v2 --branch` carries the whole header.** Branch, upstream,
  ahead/behind, changed and untracked counts — one spawn, one parser, one test. The remote address
  is the only second call. `--no-optional-locks` keeps a background read from taking the index
  lock out from under a session mid-commit.
- **Real git in tests, not a faked one.** The readers are parsers over git's output; a scripted
  fake only proves the parser agrees with the fake. A temp repository signed by a fixed identity
  costs ~300ms and proves the real thing (the registry's git tests set the precedent).
- **A wide stub answers the wrong shape.** The canvas test's "every read answers `[]`" proxy
  handed the header `[]` for git facts and it threw on `.kind`. Shape the one answer the view
  reads structurally; keep the rest quiet.

## GitHub + git — Slice 3, the repository on Finish + Connect to GitHub

One `gh repo create --source --push` behind two doors: the wizard's account step and the header.

**Learned:**

- **An outcome is not an error.** "Name already exists on this account" must not 4xx/5xx the Finish
  that already made the workspace. The leaf returns `created | failed { reason }`, the route is
  always 200, and every screen words the failure next to the thing that DID succeed. Only a name gh
  could misread (`--delete`, spaces) is a `ValidationError` — before gh sees it.
- **Two doors, one fields component.** The wizard and the Connect dialog needed the same name +
  visibility pair; `GitHubRepositoryFields` keeps the wording and the naming rules in one place,
  and `suggestRepositoryName` is the one slugger (workspace name → `front-of-house`).
- **A `watch(open)` that seeds state needs `immediate: true`** when the dialog can be mounted
  already open (the test mounted it that way; production opens it later — both must seed).
- **`--source <folder>` means no cwd.** gh takes the repository path as an argument, so the
  `CommandRunner` shape from Slice 1 (`(file, args)`) carried over unchanged.
- **A shared runner's timeout is a hidden contract.** Slice 1's `defaultCommandRunner` hardcoded 10s
  for `gh auth status`; reused for `gh repo create --push` it would SIGTERM a slow push and report gh's
  last PROGRESS line ("✓ Created repository…") as the failure (reviewer catch). Timeouts ride per call
  now, and a killed process is named as such — it may have half-succeeded.
- **Busy must span the whole Finish.** The button watched only the scaffold's pending flag; during the
  push a second click re-scaffolded the folder. One `isFinishing` over both mutations.
