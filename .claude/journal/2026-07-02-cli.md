# 2026-07-02 — the CLI (D)

The D side of "complete both" — `@vynel/cli`, direction ① (a CLI over the namespaced SDK). Net-new:
neither KAFI nor letterman ships a CLI, so this is designed from scratch, thin over `@vynel/sdk`.

```
vynel knowledge search <query> -w <id> [-m fts|semantic|hybrid] [-l <n>]
vynel knowledge list          -w <id> [-k <kind>] [-l <n>]
vynel knowledge get <docId>   -w <id>
vynel knowledge status        -w <id>
vynel knowledge reindex       -w <id>
```

**Built (`apps/cli/src/`):**
- `env.ts` — Zod `VYNEL_API_URL` (the one `process.env` read; default = local api port).
- `output.ts` — `printResult` (JSON → stdout) + `formatError` (PURE: any error → `{message, exitCode}`;
  `SdkError` → `Error <status>: <message>`). Kept pure so it's unit-testable without a process exit.
- `knowledge-commands.ts` — `registerKnowledgeCommands(program, getClient)`: the 5 subcommands mapping
  args/flags → the SDK's `knowledge.*`. `getClient` injected for testability. `--mode`/`--kind` use
  commander `.choices()` so the cast to the SDK enum is runtime-safe.
- `index.ts` — `buildProgram(getClient)`: side-effect-free + exported, so tests drive the real
  commander program with a stub client.
- `bin.ts` — the executable entry (shebang): builds the real client **lazily** (`--help`/`--version`
  need no API), parses argv, catches a command action's error → stderr + exit. commander handles its
  own parse/help/version exits (no `exitOverride` — standard CLI behavior).

**Decisions:** `commander` added (direct dep; the clean fit for subcommands, already ubiquitous). No
`exitOverride` (commander's default exits are standard; `bin`'s catch handles action errors like
`SdkError`). `bin.ts`/`index.ts` split keeps `index.ts` importable with no side effects.

**Gate:** `turbo typecheck` · `pnpm test:parity` (schema/mcp/sdk) · `vitest` **506 passed / 4 skipped**
(+9 = `output.test.ts` (3) + `knowledge-commands.test.ts` (6): the args→SDK dispatch, absent-optional
omission, positional order, error propagation). **Verified end-to-end:** `vynel --help`,
`knowledge --help`, `knowledge search --help` all render the correct tree with no server running.

**Code review (Gate 3): 1 must-fix + 2 should-fix, all applied.** The reviewer traced every dispatch
path against the SDK signatures + verified the enum casts + the `bin.ts` error funnel against
commander's own source (all sound). Applied:
- *must-fix* — `printResult(data)` used the banned standalone name `data` → renamed to `payload` (the
  `{ data, error }` destructure inside the SDK is exempt — openapi-fetch's shape + generated code).
- *should-fix* — mapping tests switched `toEqual` → `toStrictEqual` (toEqual ignores `undefined` keys,
  so the "omits absent optional flags" test wasn't actually guarding its invariant).
- *should-fix* — `toInt` throws commander's `InvalidArgumentError` (idiomatic — integrates with
  commander's own formatting + names the offending option).
