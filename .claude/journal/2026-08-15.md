# 2026-08-15

## Nodes screen — pulled from Chad's `design/mission-control-prototype`

The `Nodes` word in the title bar and the constellation it opens, moved onto main file-by-file.
Chad's UI as drawn; the plumbing rebuilt to main's rules. Two projects: one API field
(`lastMessageAt` on the continuing resolve) and the whole web screen. Renamed `mission-control` →
`nodes` (Kafi's call) so the click and the code say the same word. Plan +
excluded-scope in `.claude/plans/nodes-screen-pull.md`.

**Learned:**

- **A design branch is a fork, not a queue.** `main` was 173 commits past the fork point and the
  prototype 49 — and the prototype had *deleted* things main still ships (`workspaces/groups/*`,
  `set-workspace-status.ts`). `git checkout <branch> -- <dir>` would have silently removed live
  features. Measure `merge-base` + both `rev-list --count` before deciding "pull" means merge or
  cherry-pick.
- **A UI pull can be the tip of a schema redesign.** Two of the prototype's composables looked like
  small view helpers but read `setupCompletedAt` / `parentWorkspaceId` — a two-level
  workspace→project split main never took (main went `groupId` + `status`). `Pick<T, K>` with a key
  absent from `T` is a hard typecheck error, so this surfaces at compile time rather than at
  runtime — but only if you resist "just add the field".
- **The shared-schema caller sweep is the whole fix.** Adding `lastMessageAt` to
  `ContinuingConversationResponseSchema` also changed `root.getContinuing`, which reuses it. Ship one
  route and the generated SDK type declares a field the wire never sends. Grep the *schema* name, not
  just the route.
- **Never `eslint --fix` an `eqeqeq` error on `!= null`.** The fix rewrites it to `!== null`, which
  silently stops catching `undefined`. Hand-convert to `?? null` / optional chaining, and pin the
  booleans with a test — `task-queue-summary.ts` arrived without one and its branches were exactly
  what the rewrite touched.
- **Check the icon library before porting a component.** Main had migrated wholesale to
  `@phosphor-icons/vue`; `lucide-vue-next` is not even a dependency. Typecheck catches it, but the
  house aliasing style (`PhPlus as Plus`) is the thing to match, not just the import.
- **Faithful-to-intent beat faithful-to-bytes on the title bar.** Copying the prototype's
  `text-sm`/`py-1` would have made `Nodes` sit proud of `Vynel` and `View`, because main's bar had
  since slimmed to 34px/`text-[12px]`. Chad's intent was "a word in the menu row" — main's own
  trigger classes are what preserve it.
- Gate 2 earns its place: the view landed at 741 lines and split cleanly to 269 + 4 components +
  2 composables *after* green, with the tests unchanged. Splitting during the port would have been
  improving on red.

Verified: web + api/contracts/sdk typecheck clean; 723 tests / 108 files green; eslint clean on every
touched file (one pre-existing `eqeqeq` error left alone in `use-workspace-status.ts`).
